Probes, Logs & Debugging

Health checks, logs, metrics, and a repeatable method to debug failing applications. Related labs: 08, 13, 15.

The three probes

ProbeOn failureUse for
startupProbeContainer killed after failureThreshold; disables the other probes until it succeedsSlow-starting apps
livenessProbeContainer restartedDeadlocks, hung processes
readinessProbePod removed from Service endpoints (no restart)Warm-up, dependencies down, overload
containers:
  - name: app
    image: my-app:1.0
    startupProbe:
      httpGet: { path: /healthz, port: 8080 }
      failureThreshold: 30          # 30 x 10s = 5 minutes to start
      periodSeconds: 10
    livenessProbe:
      httpGet: { path: /healthz, port: 8080 }   # 200-399 = success
      initialDelaySeconds: 5
      periodSeconds: 10
      timeoutSeconds: 1
      failureThreshold: 3
    readinessProbe:
      tcpSocket: { port: 8080 }     # also: exec: {command: [...]}, grpc: {port: 9090}
      periodSeconds: 5
      successThreshold: 1

Lab 15 tip: the probe port must match the port the app really listens on, and the path must exist. A wrong liveness probe produces a restart loop with Liveness probe failed events.

Logs

kubectl logs web                          # single-container Pod
kubectl logs web -c sidecar               # pick a container
kubectl logs web -p                       # previous (crashed) instance
kubectl logs web -f --tail=50 --since=10m
kubectl logs deploy/web                   # one Pod of the Deployment
kubectl logs -l app=web --all-containers --prefix -f
kubectl logs job/pi

Kubernetes has no built-in cluster logging: apps write to stdout/stderr, the runtime writes files in /var/log/pods, and a node agent (DaemonSet) or a sidecar ships them.

Metrics

kubectl top nodes
kubectl top pods -A --sort-by=memory
kubectl top pod web --containers

Requires metrics-server. It also feeds the HorizontalPodAutoscaler. Typical CKA task: "write the name of the Pod using the most CPU to /opt/answer.txt".

kubectl top pod -n prod --sort-by=cpu --no-headers | head -1 | awk '{print $1}' > /opt/answer.txt

Debugging method

kubectl get pods -o wide                              # status, restarts, node
kubectl describe pod web                              # events at the bottom!
kubectl logs web --previous
kubectl get events --sort-by=.metadata.creationTimestamp
kubectl events --for pod/web
kubectl get pod web -o jsonpath='{.status.containerStatuses[0].lastState}'
kubectl exec -it web -- sh                            # check env, files, connectivity
kubectl debug -it web --image=busybox:1.36 --target=app   # ephemeral container (distroless images)
kubectl debug web -it --copy-to=web-dbg --container=app -- sh   # copy of the Pod with a shell
kubectl debug node/node1 -it --image=busybox:1.36    # node shell, host fs at /host
kubectl run curl --image=curlimages/curl --rm -it --restart=Never -- curl -sv http://web:80

Exit codes cheat sheet

  • 0: finished normally (bad for a long-running server, fine for a Job).
  • 1: application error. Read the logs.
  • 126 / 127: command not executable / not found. Check command and args.
  • 137: SIGKILL, often OOMKilled or a failed liveness probe.
  • 143: SIGTERM, graceful stop.
