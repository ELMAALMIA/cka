Deployments

kubectl create deployment web --image=nginx:1.24 --replicas=3 --port=80 --dry-run=client -o yaml > deploy.yaml
kubectl scale deployment web --replicas=5
kubectl set image deployment/web nginx=nginx:1.25          # container=image
kubectl annotate deployment/web kubernetes.io/change-cause="upgrade to 1.25"
kubectl rollout status deployment/web
kubectl rollout history deployment/web
kubectl rollout history deployment/web --revision=2
kubectl rollout undo deployment/web                        # previous revision
kubectl rollout undo deployment/web --to-revision=1
kubectl rollout pause deployment/web ; kubectl rollout resume deployment/web
kubectl rollout restart deployment/web                     # re-roll all Pods (new env from ConfigMap, etc.)
spec:
  replicas: 5
  revisionHistoryLimit: 10
  progressDeadlineSeconds: 600
  strategy:
    type: RollingUpdate            # or Recreate
    rollingUpdate:
      maxSurge: 25%                # extra Pods allowed above replicas
      maxUnavailable: 25%          # Pods allowed to be missing
  selector:
    matchLabels: { app: web }      # immutable once created
  template:
    metadata:
      labels: { app: web }         # must match selector
    spec: { ... }
  • Every change to spec.template creates a new ReplicaSet and a new revision. Scaling does not.
  • The selector is immutable; changing it is rejected.
  • Rollback = scale the old ReplicaSet back up. Old ReplicaSets are kept up to revisionHistoryLimit.
  • Deprecated API versions (extensions/v1beta1, apps/v1beta2) must become apps/v1; apps/v1 requires an explicit selector (lab 04).

Deployment strategies by hand

  • Canary (lab 09): two Deployments share the label the Service selects (app: storefront) and differ on a second label (track: stable|canary). Traffic split ≈ ratio of ready Pods: 8 stable + 2 canary ≈ 80/20.
  • Blue/green: two full-size Deployments with version: blue|green; flip the Service selector to switch all traffic at once.
  • Recreate: downtime accepted, needed when two versions cannot coexist (schema locks, RWO volumes).

Jobs and CronJobs

kubectl create job pi --image=perl:5.34 -- perl -Mbignum=bpi -wle 'print bpi(2000)'
kubectl create cronjob backup --image=busybox:1.36 --schedule="*/30 * * * *" -- sh -c 'date; echo backup'
kubectl create job manual-run --from=cronjob/backup
kubectl get jobs,cronjobs ; kubectl logs job/pi
apiVersion: batch/v1
kind: CronJob
metadata: { name: backup }
spec:
  schedule: "*/30 * * * *"           # min hour dom month dow
  concurrencyPolicy: Forbid          # Allow | Forbid | Replace
  startingDeadlineSeconds: 200       # skip run if it could not start within 200s
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  suspend: false
  jobTemplate:
    spec:
      completions: 1
      parallelism: 1
      backoffLimit: 4                # retries before the Job is Failed
      activeDeadlineSeconds: 600     # kill the Job after 10 min
      ttlSecondsAfterFinished: 3600
      template:
        spec:
          restartPolicy: OnFailure   # OnFailure or Never (never Always)
          containers:
            - name: backup
              image: busybox:1.36
              command: ["sh", "-c", "date; echo backup"]
Cron fields: minute hour day-of-month month day-of-week. */5 * * * * every 5 minutes, 0 2 * * * daily at 02:00, 0 */6 * * * every 6 hours, 30 9 * * 1-5 weekdays at 09:30.

Scaling and autoscaling

kubectl scale deployment web --replicas=3
kubectl scale statefulset db --replicas=3
kubectl autoscale deployment web --min=2 --max=10 --cpu-percent=80   # creates an HPA (needs metrics-server + CPU requests)
kubectl get hpa

StatefulSet essentials

apiVersion: apps/v1
kind: StatefulSet
metadata: { name: db }
spec:
  serviceName: db                 # headless Service (clusterIP: None) -> db-0.db.ns.svc.cluster.local
  replicas: 3
  selector: { matchLabels: { app: db } }
  template: { ... }
  volumeClaimTemplates:           # one PVC per Pod: data-db-0, data-db-1, ...
    - metadata: { name: data }
      spec:
        accessModes: ["ReadWriteOnce"]
        resources: { requests: { storage: 1Gi } }

Pods are created in order 0→n and deleted in reverse. PVCs are not deleted when the StatefulSet is deleted.
