Pods, ConfigMaps, Secrets & Resources

The Pod spec is the heart of every workload. Learn the fields that exam tasks keep asking for: env, volumes, resources, init and sidecar containers. Related labs: 01, 03, 17.

Pod anatomy

apiVersion: v1
kind: Pod
metadata:
  name: web
  labels: { app: web }
spec:
  restartPolicy: Always          # Always | OnFailure | Never
  initContainers:
    - name: wait-db
      image: busybox:1.36
      command: ["sh", "-c", "until nslookup db; do sleep 2; done"]
    - name: log-shipper           # native sidecar: init container that keeps running
      image: fluent/fluent-bit
      restartPolicy: Always
  containers:
    - name: app
      image: nginx:1.25
      ports: [{ containerPort: 80 }]
      env:
        - name: MODE
          value: "prod"
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef: { name: db-creds, key: password }
        - name: POD_IP
          valueFrom:
            fieldRef: { fieldPath: status.podIP }
      envFrom:
        - configMapRef: { name: app-config }
      resources:
        requests: { cpu: "250m", memory: "128Mi" }
        limits:   { cpu: "500m", memory: "256Mi" }
      volumeMounts:
        - { name: config, mountPath: /etc/app, readOnly: true }
        - { name: scratch, mountPath: /tmp }
  volumes:
    - name: config
      configMap: { name: app-config }
    - name: scratch
      emptyDir: {}
  • Containers in a Pod share the network namespace (one IP, talk over localhost) and can share volumes. Filesystems are separate.
  • command overrides the image ENTRYPOINT, args overrides CMD.
  • Init containers run one by one to completion before app containers. A native sidecar is an init container with restartPolicy: Always (GA since 1.33).
  • Multi-container patterns: sidecar (logging, proxy), ambassador (outbound proxy), adapter (reformat output).

ConfigMaps

kubectl create configmap app-config --from-literal=MODE=prod --from-file=app.conf
kubectl create configmap app-config --from-env-file=.env
kubectl get cm app-config -o yaml

Secrets

kubectl create secret generic db-creds --from-literal=database=inventory --from-literal=password='s3cret'
kubectl create secret tls web-tls --cert=tls.crt --key=tls.key
kubectl create secret docker-registry regcred --docker-server=registry.io --docker-username=u --docker-password=p
kubectl get secret db-creds -o jsonpath='{.data.password}' | base64 -d
  • data values are base64-encoded, not encrypted. stringData accepts plain text in YAML.
  • Types: Opaque (generic), kubernetes.io/tls, kubernetes.io/dockerconfigjson, kubernetes.io/service-account-token, kubernetes.io/basic-auth.
  • Consume exactly like ConfigMaps: secretKeyRef, envFrom[].secretRef, volumes[].secret.secretName.
  • Private registry: spec.imagePullSecrets: [{name: regcred}] or attach it to the ServiceAccount.
Lab 01 gotcha: kubectl set env --from=secret/x uses the Secret key names as the variable names. When the task needs different names, edit the Deployment and use secretKeyRef.

Resources, QoS, LimitRange, ResourceQuota

  • requests: reserved for scheduling. limits: enforced at runtime. CPU over the limit is throttled; memory over the limit is OOMKilled (exit code 137).
  • Units: CPU 1 = 1 core = 1000m. Memory Mi/Gi (binary) vs M/G (decimal).
  • QoS: Guaranteed (requests = limits for CPU and memory in every container), Burstable (something set), BestEffort (nothing set). Eviction order under node pressure: BestEffort → Burstable → Guaranteed.
  • LimitRange (per namespace): default requests/limits injected into containers, plus min/max per container or Pod. Admission rejects Pods outside the bounds.
  • ResourceQuota (per namespace): caps the total (requests.cpu, limits.memory, pods, persistentvolumeclaims, ...). When a quota covers a resource, Pods must set it, or a LimitRange default must exist.
apiVersion: v1
kind: LimitRange
metadata: { name: defaults, namespace: team-a }
spec:
  limits:
    - type: Container
      default:        { cpu: "500m", memory: "256Mi" }   # default limits
      defaultRequest: { cpu: "100m", memory: "128Mi" }   # default requests
      max:            { cpu: "1",    memory: "1Gi" }
---
apiVersion: v1
kind: ResourceQuota
metadata: { name: team-quota, namespace: team-a }
spec:
  hard: { requests.cpu: "4", requests.memory: "8Gi", limits.cpu: "8", pods: "20" }
kubectl set resources deployment web --requests=cpu=100m,memory=128Mi --limits=cpu=500m,memory=256Mi
kubectl describe quota -n team-a
kubectl describe limitrange -n team-a
kubectl top pod -n team-a            # needs metrics-server

Handy Pod commands

kubectl run nginx --image=nginx --port=80 --labels=app=web --dry-run=client -o yaml > pod.yaml
kubectl run tmp --image=busybox:1.36 --rm -it --restart=Never -- sh
kubectl run tmp --image=busybox:1.36 --rm -it --restart=Never -- wget -qO- http://web
kubectl exec -it web -c app -- sh
kubectl cp web:/var/log/app.log ./app.log
kubectl get pod web -o jsonpath='{.spec.containers[*].image}'
kubectl replace --force -f pod.yaml    # recreate when a field is immutable
