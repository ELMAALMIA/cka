Services, Ingress & NetworkPolicy

From Pod IP to the outside world: Services, DNS, Ingress, the Gateway API and NetworkPolicies. Related labs: 07, 08, 11, 16.

Kubernetes network model

  • Every Pod gets its own IP; all Pods can reach all Pods without NAT. The CNI plugin makes this happen.
  • Pod IPs are ephemeral, so Services provide a stable virtual IP and DNS name in front of a set of Pods selected by labels.
  • kube-proxy (iptables / IPVS / nftables mode) implements Service IPs on every node. EndpointSlices list the ready Pod IPs behind a Service.

Service types

TypeReachable fromNotes
ClusterIP (default)Inside the clusterVirtual IP + DNS. clusterIP: None = headless (DNS returns Pod IPs)
NodePort<anyNodeIP>:<30000-32767>Includes a ClusterIP. Set nodePort explicitly if the task gives a number
LoadBalancerExternal IP from the cloud / MetalLBIncludes NodePort + ClusterIP. Stays <pending> without a provider
ExternalNameInsideCNAME to an external DNS name, no selector, no proxying
kubectl expose deployment web --name=web --port=80 --target-port=8080 --type=ClusterIP
kubectl expose deployment web --port=80 --target-port=8080 --type=NodePort
kubectl create service clusterip web --tcp=80:8080 --dry-run=client -o yaml
kubectl get svc,endpointslice -l app=web
kubectl get endpointslice -l kubernetes.io/service-name=web -o wide
kubectl port-forward svc/web 8080:80
apiVersion: v1
kind: Service
metadata: { name: web }
spec:
  type: NodePort
  selector: { app: web }          # must match Pod labels, not the Deployment's
  sessionAffinity: None            # or ClientIP
  ports:
    - name: http
      port: 80                     # Service port
      targetPort: 8080             # container port (number or port name)
      nodePort: 30080              # optional, NodePort/LoadBalancer only
      protocol: TCP
No endpoints? The selector does not match the Pod labels, the targetPort is wrong, or the Pods are not Ready (readiness probe failing). kubectl describe svc web shows Endpoints:.

DNS

  • Service: <svc>.<ns>.svc.cluster.local. From the same namespace <svc> works, from another <svc>.<ns>.
  • Pod: <ip-with-dashes>.<ns>.pod.cluster.local (rarely used). StatefulSet Pod: <pod>.<headless-svc>.<ns>.svc.cluster.local.
  • CoreDNS runs as a Deployment in kube-system; its Corefile is in the coredns ConfigMap; the Service is kube-dns.
  • Pod dnsPolicy: ClusterFirst (default), Default (node's resolv.conf), None (use dnsConfig), ClusterFirstWithHostNet.
kubectl run dns-test --image=busybox:1.36 --rm -it --restart=Never -- nslookup web.backend.svc.cluster.local
kubectl exec web -- cat /etc/resolv.conf
kubectl -n kube-system logs deploy/coredns

Ingress

Layer-7 HTTP(S) routing by host and path. Requires an Ingress controller (nginx, traefik, HAProxy...) and an IngressClass.

kubectl get ingressclass
kubectl create ingress shop --class=nginx \
  --rule="shop.example.com/=storefront:80" \
  --rule="shop.example.com/api=api:8080,tls=shop-tls"
kubectl describe ingress shop
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: shop
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  tls:
    - hosts: [shop.example.com]
      secretName: shop-tls
  rules:
    - host: shop.example.com
      http:
        paths:
          - path: /
            pathType: Prefix              # Prefix | Exact | ImplementationSpecific
            backend:
              service:
                name: storefront          # same namespace as the Ingress
                port: { number: 80 }      # or name: http

Lab 08 checklist: class name matches a controller, Service name and port exist in the same namespace, Service has endpoints, host header matches (curl -H "Host: shop.example.com" http://<ingress-ip>/).

Gateway API

The successor to Ingress, now in the CKA curriculum. Role-oriented: infra provides a GatewayClass, cluster operators create a Gateway (listeners), developers attach HTTPRoute / TCPRoute / GRPCRoute objects.

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata: { name: web-gw }
spec:
  gatewayClassName: nginx
  listeners:
    - name: http
      protocol: HTTP
      port: 80
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: { name: shop }
spec:
  parentRefs: [{ name: web-gw }]
  hostnames: ["shop.example.com"]
  rules:
    - matches: [{ path: { type: PathPrefix, value: /api } }]
      backendRefs: [{ name: api, port: 8080 }]
    - backendRefs:
        - { name: storefront, port: 80, weight: 80 }     # weighted canary
        - { name: storefront-canary, port: 80, weight: 20 }

NetworkPolicy

  • Namespaced firewall rules for Pods, enforced by the CNI (Calico, Cilium, Weave; not plain Flannel).
  • With no policy selecting a Pod, all traffic is allowed. Once any policy selects a Pod for a direction (policyTypes), only listed traffic in that direction is allowed. Policies are additive (union).
  • Peers: podSelector, namespaceSelector, ipBlock. Same list item = AND, separate items = OR.
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata: { name: api-allow, namespace: backend }
spec:
  podSelector:
    matchLabels: { app: api }          # {} selects every Pod in the namespace
  policyTypes: [Ingress, Egress]
  ingress:
    - from:
        - podSelector: { matchLabels: { app: web } }      # OR
        - namespaceSelector:                              # OR: any Pod in namespaces labelled team=ops
            matchLabels: { team: ops }
        - namespaceSelector: { matchLabels: { env: prod } }   # AND (same item): Pods app=monitor in prod namespaces
          podSelector: { matchLabels: { app: monitor } }
      ports:
        - { protocol: TCP, port: 8080 }
  egress:
    - to:
        - podSelector: { matchLabels: { app: db } }
      ports: [{ protocol: TCP, port: 5432 }]
    - to:                                                 # allow DNS
        - namespaceSelector: {}
      ports: [{ protocol: UDP, port: 53 }, { protocol: TCP, port: 53 }]
# default deny all ingress in a namespace
spec:
  podSelector: {}
  policyTypes: [Ingress]
# default deny all ingress AND egress
spec:
  podSelector: {}
  policyTypes: [Ingress, Egress]

Namespaces carry the automatic label kubernetes.io/metadata.name=<ns>, handy for namespaceSelector. Test with kubectl exec web -- wget -qO- --timeout=2 http://api:8080.
