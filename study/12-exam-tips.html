First two minutes: shell setup

alias k=kubectl                                  # often already set
source <(kubectl completion bash); complete -o default -F __start_kubectl k
export do="--dry-run=client -o yaml"
export now="--force --grace-period=0"
cat >> ~/.vimrc <<'EOF'
set expandtab tabstop=2 shiftwidth=2
EOF

Reading and filtering output

k get pods -A -o wide --show-labels
k get pods -l app=web,tier!=db
k get pods --field-selector=status.phase=Running,spec.nodeName=w1
k get pods -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.podIP}{"\n"}{end}'
k get nodes -o jsonpath='{.items[*].status.addresses[?(@.type=="InternalIP")].address}'
k get pods -o custom-columns=NAME:.metadata.name,IMAGE:.spec.containers[0].image
k get pv --sort-by=.spec.capacity.storage
k explain pod.spec.containers.livenessProbe --recursive | less

Editing objects quickly

  • k edit deploy web for small changes to controllers.
  • Pods are mostly immutable. k edit pod saves a copy in /tmp on failure, then run k replace --force -f /tmp/kubectl-edit-*.yaml.
  • k get deploy web -o yaml > web.yaml, edit, k apply -f web.yaml when the change is large.
  • k patch deploy web -p '{"spec":{"replicas":3}}' for scripted one-liners.

Time strategy

  1. Read the task weight. Do every task in one quick pass; flag anything that takes more than about 7 minutes and come back later.
  2. Always run the kubectl config use-context line given in the task and set the namespace.
  3. Generate YAML imperatively, then edit. Copy snippets from kubernetes.io only for things kubectl cannot generate (PV, PVC, NetworkPolicy, probes, securityContext).
  4. Verify every task: get -o yaml, rollout status, a test Pod with wget or nslookup.
  5. Respect constraints like "do not modify X". Write output files to the exact path asked.
  6. On tasks that need ssh to a node, remember to exit back to the base host afterwards.
