Scheduling, Taints & Affinity

How Pods land on nodes, how to steer them, and what to look at when they stay Pending.

How the scheduler works

  1. Watches for Pods with an empty spec.nodeName.
  2. Filtering: removes nodes that cannot host the Pod (resources, taints, nodeSelector, required affinity, volume topology, ports).
  3. Scoring: ranks remaining nodes (preferred affinity, spreading, image locality, least allocated).
  4. Binding: writes nodeName; the kubelet takes over.

Set spec.nodeName yourself and the scheduler is bypassed entirely. Set spec.schedulerName to use another scheduler.

nodeSelector and node affinity

kubectl label nodes node2 disktype=ssd
kubectl get nodes --show-labels
spec:
  nodeSelector:
    disktype: ssd                      # simple AND of labels
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:     # hard
        nodeSelectorTerms:
          - matchExpressions:
              - { key: topology.kubernetes.io/zone, operator: In, values: [eu-west-1a, eu-west-1b] }
      preferredDuringSchedulingIgnoredDuringExecution:    # soft, weighted 1-100
        - weight: 80
          preference:
            matchExpressions:
              - { key: disktype, operator: In, values: [ssd] }

Operators: In, NotIn, Exists, DoesNotExist, Gt, Lt. Multiple nodeSelectorTerms are ORed; expressions inside one term are ANDed.

Pod affinity and anti-affinity

affinity:
  podAntiAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchLabels: { app: web }
        topologyKey: kubernetes.io/hostname       # one web Pod per node
  podAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector: { matchLabels: { app: cache } }
          topologyKey: topology.kubernetes.io/zone  # prefer same zone as cache
topologySpreadConstraints:               # modern way to spread evenly
  - maxSkew: 1
    topologyKey: kubernetes.io/hostname
    whenUnsatisfiable: DoNotSchedule       # or ScheduleAnyway
    labelSelector: { matchLabels: { app: web } }

Taints and tolerations

Taints live on nodes and repel Pods. Tolerations live on Pods and allow (not force) scheduling onto tainted nodes.

kubectl taint nodes node1 dedicated=gpu:NoSchedule        # add
kubectl taint nodes node1 dedicated=gpu:NoSchedule-       # remove (trailing dash)
kubectl describe node node1 | grep -i taints
kubectl taint nodes --all node-role.kubernetes.io/control-plane-   # allow workloads on control plane
EffectNew PodsRunning Pods
NoScheduleBlocked unless toleratedUntouched
PreferNoScheduleAvoided if possibleUntouched
NoExecuteBlockedEvicted unless tolerated (optionally after tolerationSeconds)
tolerations:
  - key: dedicated
    operator: Equal          # Equal needs value; Exists does not
    value: gpu
    effect: NoSchedule
  - key: node.kubernetes.io/not-ready
    operator: Exists
    effect: NoExecute
    tolerationSeconds: 60    # default is 300 for not-ready / unreachable
Pattern for dedicated nodes: taint the node and add a nodeSelector/affinity on the Pod. The taint keeps others out; the selector keeps your Pod in.

Static Pods

  • Created by the kubelet from files in staticPodPath (/etc/kubernetes/manifests). Find the path in /var/lib/kubelet/config.yaml.
  • The API server shows a read-only mirror Pod named <name>-<nodename>. Deleting it with kubectl is useless; move or delete the file on the node.
  • Control-plane components on kubeadm are static Pods. A typo in their manifest is a classic troubleshooting task.
kubectl run static-web --image=nginx --dry-run=client -o yaml | sudo tee /etc/kubernetes/manifests/static-web.yaml
sudo systemctl restart kubelet     # usually not needed, the kubelet watches the directory

Priority and preemption

apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata: { name: high }
value: 100000
globalDefault: false
preemptionPolicy: PreemptLowerPriority     # or Never
description: "Critical services"
---
# in the Pod spec
spec:
  priorityClassName: high

Node maintenance

kubectl cordon node1                                   # SchedulingDisabled, nothing new lands
kubectl drain node1 --ignore-daemonsets --delete-emptydir-data --force   # evict everything
# ... upgrade / reboot ...
kubectl uncordon node1

--force is needed for Pods without a controller (bare Pods). PodDisruptionBudgets can block a drain; check with kubectl get pdb -A.

Why is my Pod Pending?

kubectl describe pod web | sed -n '/Events/,$p'
  • Insufficient cpu/memory → lower requests or add capacity.
  • node(s) had untolerated taint → add a toleration or remove the taint.
  • didn't match Pod's node affinity/selector → fix labels.
  • unbound immediate PersistentVolumeClaims → PVC is Pending (see Storage).
  • No events at all → the scheduler itself is down (kubectl -n kube-system get pods).
