Troubleshooting Clusters

Troubleshooting is the largest CKA domain. Learn to read the symptom, guess which component owns it, and know where its logs live when kubectl itself does not work.

Control-plane components (static Pods)

kubectl -n kube-system get pods -o wide
kubectl -n kube-system describe pod kube-apiserver-cp1
kubectl -n kube-system logs kube-controller-manager-cp1

# when the API server is down, kubectl is useless:
sudo crictl ps -a | grep -E 'apiserver|etcd|scheduler|controller'
sudo crictl logs <container-id>
sudo ls /var/log/pods/ ; sudo tail -50 /var/log/pods/kube-system_kube-apiserver-*/kube-apiserver/*.log
sudo vi /etc/kubernetes/manifests/kube-apiserver.yaml     # kubelet reapplies automatically
Classic broken-cluster tricks: wrong image tag, typo in a flag name, wrong certificate path, wrong etcd endpoint or port (2379), wrong --kubeconfig path in the scheduler or controller-manager manifest, wrong hostPath volume. Compare with a healthy manifest and look at what is different.

Never save a backup copy inside /etc/kubernetes/manifests: the kubelet would start it as a second Pod. Copy to /tmp instead.

Worker nodes and the kubelet

kubectl get nodes
kubectl describe node w1                          # Conditions: Ready, MemoryPressure, DiskPressure, PIDPressure
ssh w1
sudo systemctl status kubelet
sudo journalctl -u kubelet -n 100 --no-pager
sudo systemctl status containerd
cat /var/lib/kubelet/config.yaml
cat /usr/lib/systemd/system/kubelet.service.d/10-kubeadm.conf
cat /var/lib/kubelet/kubeadm-flags.env
sudo systemctl daemon-reload && sudo systemctl restart kubelet && sudo systemctl enable kubelet
  • Kubelet stopped or disabled: start it and enable it so it survives reboots.
  • Wrong kubelet binary path in the unit file, wrong config path, wrong CA file path, wrong API server address in /etc/kubernetes/kubelet.conf.
  • cgroup driver mismatch between kubelet (cgroupDriver: systemd) and containerd (SystemdCgroup = true).
  • Swap enabled. Expired kubelet certificate in /var/lib/kubelet/pki.

Networking

kubectl -n kube-system get pods -l k8s-app=kube-dns
kubectl -n kube-system get svc kube-dns ; kubectl -n kube-system get endpointslice -l kubernetes.io/service-name=kube-dns
kubectl -n kube-system get cm coredns -o yaml
kubectl -n kube-system get ds kube-proxy ; kubectl -n kube-system logs ds/kube-proxy
kubectl -n kube-system get cm kube-proxy -o yaml      # mode, clusterCIDR
ls /etc/cni/net.d/ ; ls /opt/cni/bin/
kubectl run t --image=busybox:1.36 --rm -it --restart=Never -- sh -c 'nslookup kubernetes.default; wget -qO- --timeout=2 http://web'
  • Check the kubelet clusterDNS IP equals the kube-dns Service ClusterIP.
  • CoreDNS in CrashLoopBackOff with loop detected means it forwards to itself. Fix the forward line or the node's resolv.conf.
  • Pod CIDR given to kubeadm init must match the CNI configuration.

Application failures

Follow the chain from the outside in: Ingress → Service → Endpoints → Pod → container.

kubectl describe ingress shop                         # backend service/port exist?
kubectl get svc web -o wide ; kubectl describe svc web    # selector, targetPort, Endpoints
kubectl get pods -l app=web --show-labels                 # labels match the selector?
kubectl describe pod <pod>                               # events
kubectl logs <pod> --previous                            # crash reason
kubectl exec -it <pod> -- netstat -tlnp                  # really listening on targetPort?

Resource monitoring

kubectl top nodes ; kubectl top pods -A --sort-by=memory
kubectl describe node w1 | sed -n '/Allocated resources/,/Events/p'
kubectl get events -A --field-selector type=Warning --sort-by=.lastTimestamp

A 5-step routine for any broken cluster task

  1. kubectl get nodes and kubectl get pods -A | grep -v Running to see the scope.
  2. describe the failing object and read the Events.
  3. Logs: kubectl logs, or crictl logs / journalctl when the API is down.
  4. Compare the config with what it should be (manifest, systemd unit, ConfigMap).
  5. Fix one thing, wait, re-check. Verify from the API server, not from your edited file.
